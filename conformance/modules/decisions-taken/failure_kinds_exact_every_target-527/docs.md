# Decision 527 — `Failure`'s kinds exact on every target: wasm never imitates a host raise; an unmarked raise is `crash`; a failing `assert` and an integer division by zero are `panic`; a host raise's message is `~tp` without the stack.

The program runs five thunks under `attempt` and prints each `Failure`'s kind and message. `rkBumpTag("")` is rakun refusing an empty tag: its runtime raises a marked `panic`, so the line is `panic rakun: a tag is a non-empty string (rkBumpTag)`. `parseInt("x")` is a binding the program declares itself with `#[compiler.external(.Erlang(…))]` and no `result: true`; every call of such a binding is wrapped, so its raise is marked and answers `host`, its message the reason printed by `~tp` without the stack (`badarg`). `10 / zero` is an integer division by zero: on erlang and beam it raises a marked `panic`, as commonJS does, never a bare `badarith` read as `host`. `checked(zero)` fails its `assert`, which is a `panic` whose message names the asserted expression and its location (`assertion failed: n > 0 at src/main.bp:…`), so that line prints `panic true`. The last thunk succeeds: `ok 42`. A raise nothing marks — a failing match, a fault of emitted code — answers `crash`. On wasm nothing imitates a host raise: a JavaScript host raising into wasm is a real `host`, and on wasmtime, where no host raises, a host case narrows its targets; rakun is erlang-only, so this program runs on erlang and beam.

Cells in this repository that prove it: none yet; rakun's runtime raises are covered by `modules/rakun/test/erlang_runtime_test.bp`, and the cells come with front 150's Conformance step.
