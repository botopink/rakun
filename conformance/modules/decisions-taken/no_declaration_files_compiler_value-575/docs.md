# Decision 575 — No declaration files; a builtin is a std declaration marked `#[builtin]`; a `declare fn` names its host sources with `#[compiler.external(…)]`; a build-time body talks to the compiler through the keyword `compiler`; `comptime` and `syntax` on a parameter say how an argument arrives.

The program uses the pieces rakun's own wiring is made of. `nowMs` is a `declare fn` whose host source is named by `#[compiler.external(.Erlang(…))]` on the declaration itself, the same form `modules/rakun/src/runtime.bp` uses for `rkScan`; there is no `.d.bp` file anywhere. `tagged` is a decorator: its first parameter, `syntax decl`, is the annotated declaration as the compiler hands it over, and its second, `comptime label`, is the annotation's argument as a build value. Its body talks to the compiler through `compiler`, imported from std like any other name: it checks the declaration's kind with `compiler.kind`, reads its name with `compiler.name`, records a `Tag` with `compiler.setMeta`, adds the typed member `label()` with `compiler.addMember`, and compiles `rkScan(name)` into the init list with `compiler.init`, so it runs once before `main`. The program prints `billing mail`, the two names rakun's scan registry holds (`Invoices` first, in source order) and `true`.

`#[builtin]` is std's alone: a program or a library that writes it is refused `setBuiltin-outside-std`, and the names that used to be `@print`, `@panic` and the like are ordinary std declarations imported from their modules (`terminal.print` here). The removed `@emit`, `@code` and `@expr` have no replacement but `compiler.init` and the typed outputs.

Cells in this repository that prove it: `rakun/plug-and-play/boot_modules` and `rakun/plug-and-play/module_not_a_component` (a decorator, `#[rakun.module]`, writing its executor with `compiler.init` and refusing with `compiler.fail`). rakun's ~60 `val __rk*` registrations move to `compiler.init` in front 165 s10.
